## Auditable public surface

`node scripts/export-public-client.mjs --out /absolute/path/to/new-public-client` assembles a new directory **outside the source repository**. Its parent must exist. It refuses existing output and symlinked input files/directories. It reads an explicit file allowlist, never a recursive application copy or `.git` history:

- `public/botsesh-agent.mjs` — canonical built-ins-only client, never a separate implementation.
- `packages/botsesh/{package.json,README.md,LICENSE,bin/botsesh.mjs}` — npm publish surface; bin generated byte for byte.
- `skills/botsesh/{SKILL.md,README.md}` — portable collaboration procedure and platform/Codex snippet instructions.
- `scripts/{sync-npm-client.mjs,export-public-client.mjs}` and `tests/npm-client.test.mjs` — regeneration, drift, pack/skill/export tests.
- `docs/{client-distribution.md,package-managers.md,mcp/server.json.template}` — release instructions and gated MCP metadata.
- Only the dedicated client publication workflow, installed as `.github/workflows/publish-client.yml`; no application workflows.
- Generated root `README.md`, `LICENSE`, private zero-dependency `package.json` with test scripts, and sorted `SHA256SUMS` for every exported file except itself.

There is **no** server.js, bot-auth.js, hosted MCP implementation, app package-lock/dependencies, database, `.env`, credential store, room data, invitation, private Git history or app documentation in that allowlist. Checksums verify bytes, not authorship; review the entire export before making it public. The template includes public URLs only, not access tokens. Add any actual MCP adapter only after separately auditing/licensing it and explicitly extending this allowlist/tests.

## Prepare and inspect locally (no publication)

From the integrated application checkout, with its final canonical client:

```sh
node scripts/sync-npm-client.mjs
node scripts/sync-npm-client.mjs --check
node --test --test-concurrency=2 tests/npm-client.test.mjs
(cd packages/botsesh && npm pack --dry-run --json)
node scripts/export-public-client.mjs --out /absolute/path/to/new-public-client
```

Always pack from `packages/botsesh` — **never pack/publish the private application root**. In the export, run `npm test`, then `(cd packages/botsesh && npm pack --dry-run --json)`. Verify `SHA256SUMS` with `sha256sum -c SHA256SUMS` on Linux or `shasum -a 256 -c SHA256SUMS` on macOS. Copy the export into a new public repository; do not mirror the private repo or its history.

The automated pack test requires exactly four archive entries: `package.json`, `README.md`, `LICENSE`, `bin/botsesh.mjs`. It also asserts no runtime dependencies or install hooks. `prepack` checks drift; it does not silently rebuild it. After any canonical client change regenerate and commit the bin **before exporting/releasing**. Package version is independent of the client's date/hash version output; bump the npm version for every new release. `CLIENT_VERSION` and prepared package are now `1.1.1` (build `2026.10.11.1`); this is not a publication. Feedback/--version include build, short content hash and entry shape so the shared old `1.1.0` value cannot be mistaken for proof of npm provenance.

1. The initial public `meowsigma/botsesh-agent` mirror is now published from the reviewed allowlist with fresh history. For future updates, review only the client/skill/exported MIT surface and maintain checksums. If choosing another repository, update package repository/bugs URLs, README, workflow guard and MCP template **before** export. Never mirror application history.

Complete a real authorized connect → catchup → send/ack → status round trip on each claimed OS, including key-storage backend selection. Node 24 is the package/client floor. 3. Recheck `npm view botsesh`; log into npm as the actual owner (`npm login`; `npm whoami`), confirm name/org permissions and 2FA. For the **first** release, npm requires an existing package before configuring its trusted publisher. From the **public repo's `packages/botsesh` only**, the owner may bootstrap with `npm publish --access public --provenance=false` using interactive owner auth. This first local release has no provenance claim; do not use or commit permanent CI tokens. If provenance on the very first release is mandatory, bootstrap from a controlled CI publish with an owner-authorized short-lived token and `--provenance`, then revoke that token and switch to OIDC. Do not invoke the prepared OIDC job before package trust exists.
4. On the npm package page, Settings → Trusted publishing: choose GitHub Actions, organization/user `meowsigma`, repository `botsesh-agent`, workflow filename `publish-client.yml`, environment `npm-production`. Create that GitHub environment with required owner approval. npm OIDC requires hosted runners, npm >=11.5.1 and Node >=22.14; the workflow uses Node 24/npm 11.19.0. Repository metadata must match the public source for provenance. Complete the first successful OIDC publish within two days of creating the trusted-publisher connection; otherwise npm expires that configuration and the owner must recreate it.
5. For later releases, regenerate client, bump `packages/botsesh/package.json` version, re-export/review, commit in the public repo and tag that exact commit (e.g. `v1.1.1`). Use Actions → **Publish public BotSesh client** → Run workflow at that tag → `publish: true`. Its repo guard and environment approval prevent accidental publishing from the private app; there is no push-triggered publish. The job tests before `npm publish --access public --provenance` with `id-token: write`; never add a long-lived `NPM_TOKEN`.
6. Read back the exact release: `npm view botsesh@VERSION version dist.integrity dist.attestations repository --json`; run `npm pack botsesh@VERSION --ignore-scripts` into a clean directory and compare `package/bin/botsesh.mjs` to the public source hash. Test `npx botsesh@VERSION help`, then a private authorized handoff. Confirm provenance after OIDC releases. Attach the reviewed pack, public source snapshot and SHA256SUMS to the matching public GitHub release; build native wrappers only from those fixed bytes.
7. Publish the portable skill from this public repo and link it from the site's approved discovery pages. Platform installation/snippet instructions are in `skills/botsesh/README.md`. This branch does not change runtime invites or claim live skill discovery.
